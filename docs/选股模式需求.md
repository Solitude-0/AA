# 选股模式筛选 · 需求与实现对照

> 2026-10-23 落地。原始需求是一份"选股模式筛选面板"的交互稿（三栏工作台 + 六种进攻模式 + 通用筛选）。
> 本文记录**每条判定条件最终是怎么实现的、数据来自哪里、哪几条做不到**——做不到的宁可标"不可判定"，也不拿近似值冒充。

---

## 0. 落地位置：不新开页面，挂进现有三栏

需求写的是"左侧筛选面板 / 中间候选列表 / 右侧个股分时详情"的三栏工作台。现有看板已经是三栏
（左：指数·宽度·板块矩阵 / 中：个股表 / 右：资金流·盘口·异动），所以不另起炉灶：

| 需求的区域 | 落到现有界面 |
|---|---|
| 左侧 选股模式面板 | 中间栏顶部新增「选股模式」卡片（`view==='pick'` 时展开），点「选股」tab 进入 |
| 中间 候选股票列表 | 复用个股表：新增「模式 / 分时 / 分」三列，价格涨幅仍走 WS 增量刷新 |
| 右侧 个股分时详情 | 复用现有详情抽屉：分时 + 8 周期 K 线 + 五档盘口 + 逐笔 + 四档资金流已全在里面 |

切 tab 即切换：全市场 / 自选 / **选股**。

## 1. 核心难点：分时序列在全市场拿不到

六个模式里有四个必须看**分时序列**（平台突破、龙回头未破前低、尾盘抢筹、均线金叉），
而分时只能逐只拉（东财/腾讯都是单只接口）。5343 只 × 1 次 = 不可能。

所以全部判定拆成两级漏斗：

```
全市场 5343
   │  ① 通用筛选（价格/市值/换手/成交额/板块/排ST）—— 纯快照字段，0 次额外请求
   ▼
A 层闸门（每个模式各判一次，一只股票可同时命中多个模式）
   │  ② A 层模式（开盘突破 / 盘口内外盘）：到此就出结论
   │  ③ B 层模式：每种模式按自己特征取前 10 只候选，去重后并发拉 1m K 线（6 并发，墙钟上限 10 s）
   ▼
B 层精判 → 合并去重 → 按分数排序 → 前 50 只返回
```

实测（14:35，全 6 模式）：通用筛选 5342 只 → A 层候选 4000+ → 精筛 20 只 → 命中 215 只，**约 2~6 s**。
A 层模式在全市场范围内**全量判定、不抽样**；只有 B 层模式受预算限制，被截断时接口会返回
`truncated=true` 和具体哪几个模式被截断（`trunc_modes`），页面显示"每种模式按特征各取前 N 只，可能截断"。

## 2. 六种进攻模式：判定条件与字段来源

参数都是**可调**的（页面上「参数」一行，或直接改 URL 查询串），默认值如下。

### ① 开盘突破 `gap`（A 层）

| 条件 | 实现 | 数据来源 |
|---|---|---|
| 集合竞价涨幅 ≥ 1.5% | `开盘价 / 昨收 − 1` | 快照 `open` / `prev`。**9:25 集合竞价的撮合结果就是开盘价**，所以这是精确等价，不是近似 |
| 量比 ≥ 1.5 | 快照 `量比` 字段 | 腾讯快照第 49 位 |
| 开盘后未回补缺口 | `当日最低 ≥ 开盘价` | 快照 `low` / `open`。日线最低是分时最低的**包络**，所以这条比"分时线不回补"更严 |
| 现价不弱于开盘 | `现价 ≥ 开盘价` 且 `涨幅 ≥ 竞价涨幅` | 快照 |

> 这条模式 A 层就能完全判定，不需要分时；缩略图是后补的（见 §5）。

### ② 盘口内外盘 `order`（A 层）

| 条件 | 实现 | 数据来源 |
|---|---|---|
| 外盘/内盘 ≥ 1.5 | `外盘量 / 内盘量`，内盘为 0 时返回 99 | 快照 `外盘` / `内盘`（腾讯第 7/8 位） |
| 主动买盘压制 | 同上 | — |
| 现价在开盘价上方 | `现价 ≥ 开盘价` | 快照 |
| 连续大单买入 ≥ 3 笔 | **不可判定** | 逐笔成交只有自选池前 20 只有采集，全市场没有 |

### ③ 分时平台突破 `platform`（B 层）

| 条件 | 实现 |
|---|---|
| 前段横盘 ≥ 20 分钟 | 取 1m 序列中「倒数第 21 根到倒数第 2 根」作为平台段，跨度不足 25 根直接不判 |
| 横盘振幅 ≤ 1.2% | `(平台段最高 − 最低) / 平台段均价` |
| 突破平台上沿 | `现价 > 平台段最高价` |
| 突破时放量 ≥ 1.5× | 最后一根 1m 成交量 ≥ 平台段均量 × 1.5 |

### ④ 涨停龙回头 `dragon`（B 层）

| 条件 | 实现 |
|---|---|
| 盘中触及涨停 | `当日最高 ≥ 涨停价 × 0.999`（留 0.1% 容差：涨停价按四舍五入算，边界会差 1 分） |
| 已开板（不是封住的） | `现价 < 涨停价` |
| 回调幅度 ≤ 3% | `(当日最高 − 现价) / 当日最高` |
| 未跌破涨停前分时低点 | 在 1m 里找**第一根触及涨停价的 bar**，取它之前所有 bar 的最低价，要求 `现价 ≥ 该低点 × 0.995` |
| 外盘占优 | 外盘/内盘 ≥ 1（A 层已含 1.5 的更严版本时会同时出现在 `why` 里） |

### ⑤ 分时均线金叉 `ma`（B 层）

| 条件 | 实现 |
|---|---|
| 5 分钟 MA5 上穿 MA10 | 1m 聚合 5m（每 5 根合并），最近 3 根内出现 `MA5 > MA10 且前一根 MA5 ≤ MA10` |
| 站上 MA5 | `最后一根收盘 > MA5` |
| MACD 红柱放大 | 5m 收盘算 EMA12/EMA26 → DIF → DEA(9) → `hist = (DIF−DEA)×2`，要求 `hist[-1] > 0 且 hist[-1] ≥ hist[-2]` |

### ⑥ 尾盘抢筹 `tail`（B 层）

| 条件 | 实现 |
|---|---|
| 14:30 后涨幅 ≥ 3% | 在 1m 里找第一根时间 ≥ `14:30` 的 bar 作为锚点，`现价 / 锚点收盘 − 1` |
| 现价 ≥ 当日最高 95% | 快照 `price` / `high`（A 层闸门已用） |
| 收盘不破 14:30 价 | 14:30 后所有 bar 的最低价 ≤ 现价 |

## 3. 通用筛选

| 条件 | 参数 | 默认 |
|---|---|---|
| 股价区间 | `price_min` / `price_max` | 3 ~ 100 元 |
| 流通/总市值区间 | `cap_min` / `cap_max` | 30 ~ 800 亿（用总市值） |
| 换手率区间 | `to_min` / `to_max` | 2 ~ 15% |
| 成交额下限 | `amt_min` | 1 亿 |
| 板块 | `boards` | 空 = 全部（`sh` 沪主板 / `sz` 深主板 / `cyb` 创业板 / `kcb` 科创板 / `bj` 北证，代码前缀判定） |
| 排除 | `excl_st` / `excl_halt` / `excl_zt` | 排 ST / 排停牌 / 排一字板（默认不排一字板） |
| 均线 | — | **不可判定**：日线 MA5/MA10/MA20 需要逐只拉日 K，全市场不可行；B 层的 5m MA 是盘中均线，口径不同 |
| 个股标签（次新 / 高送转 / 回购 / 业绩预增） | — | **无数据源**，不编 |

## 4. 综合评分（100 分制，刻意可解释）

| 项 | 权重 | 规则 |
|---|---|---|
| 强度 | 40 | 涨幅，0% → 0 分，≥20% → 满分 |
| 量能 | 20 | 量比，3 倍 → 满分 |
| 承接 | 20 | 外盘占比，50% → 0 分，70% → 满分（50% 是中性，直接用占比当分会把中性盘算成加分） |
| 形态 | 20 | 命中模式数 × 10，上限 20 |

排序默认 `score`，也支持 `pct` / `amt` / `vr`。`why` 字段给出每条命中的具体依据（例如
`涨停龙回头(回踩 1.2% 未破 23.86)`），鼠标悬停即可看到。

## 5. 分时缩略图为什么是异步的

A 层模式不需要分时就能判定，但表格要画缩略图。如果为了画图给 50 行都拉一遍 1m，主接口就会从
2 s 变成 7 s。所以拆成两个接口：

- `GET /api/picker` 只返回判定结果，命中行若有分时（B 层精筛过）就带 `spark`；
- `GET /api/spark?codes=...` 批量补缩略图（≤80 只，6 并发），前端在列表渲染完之后补进来，缺图先显示 `—`。

单只 1m 的进程内缓存 TTL 是 15 s，所以连续点"执行"基本命中缓存，第二次很快。

## 6. 时段参数建议（页面参数可改，不用改代码）

| 时段 | 建议调整 | 原因 |
|---|---|---|
| 9:30–10:00 | `platform.flat_min` 降到 10、`gap.open_pct` 提到 2% | 开盘半小时本来就没有 20 分钟平台；强势票竞价更凶 |
| 10:00–11:30 | 默认值即最优 | — |
| 13:00–14:00 | `dragon.pullback` 放宽到 5% | 午后炸板回踩通常更深 |
| 14:00–14:57 | 关掉 `tail` 之外的模式，`tail.after` 提到 5% | 尾盘只做真抢筹 |
| 涨停数 < 30 只的日子 | `excl_zt` 打开 + `gap` 减半仓位 | 情绪退潮，开盘突破的持续性差（对应你笔记里的"涨停 >80 / 50~80 / <30"三档） |

> 以上是参数建议，不是交易建议。系统只做客观筛选，不产生买卖信号。

## 7. 接口契约

```
GET /api/picker/meta
→ {modes:[{k,n,lv,icon,d,params}], general:{...}, markets:[{k,n}]}

GET /api/picker?modes=gap,order&price_min=3&cap_max=800&probe=40&size=50&sort=score
→ {rows:[{c,n,p,pc,vr,to,amt,amp,cap,oa,oi,fh,avg,modes:[],why,score,spark:[]}],
   total, pool, cands, probed, per_mode, truncated, trunc_modes, dropped, timed_out,
   spark_n, modes, na, ms, session, trading, ts}

GET /api/spark?codes=600519,300750&n=60
→ {rows:{"600519":[...收盘价...]}, n}
```

`pool / cands / probed / total` 分别对应漏斗的四个台阶，页面上直接显示，避免"命中 215 只"
被误读成"全市场筛出 215 只"（其实是 A 层候选里命中、B 层精筛过的 215 只）。

## 8. 判定规则怎么验（不依赖源站）

四个 B 层模式靠 1m 分时判定，而 `push2his` 间歇性可用——线上偶遇式验证等于碰运气。
`tools/pick_rules_test.py` 手工造分时序列直接打 `picker._judge_b`，15 项断言覆盖
每条分支的通过/否两条路：

```
.venv\Scripts\python.exe tools/pick_rules_test.py
```

两个已确认的行为边界，改动前先看这两条：

- **`ma` 的 `MACD 红柱放大` 要求**：等速上涨时 DIF 增速递减，柱会先放大后收敛，
  所以股价还在涨但柱已缩短的那一刻判否。正例测试数据必须带加速度。
- **`tail` 的「尾盘破位」当前不可达**：`price < low_after` 与 `after ≥ 3%` 数学上互斥
  （锚点最低价也被计入 low_after）。不误伤，但也提供不了保护——属于待决策项。
