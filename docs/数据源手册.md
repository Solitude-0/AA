## 二、腾讯快照（主力通道）

### 2.1 请求

```
GET https://qt.gtimg.cn/q=sh600519,sz000001,bj920000
Header: User-Agent: Mozilla/5.0 ...
```

- **一次建议 ≤300 只**（实测 300 只响应 146 KB，耗时 53 ms 热 / 240 ms 冷）
- 返回 **GBK**，必须 `decode('gbk')`；用 utf-8 得到乱码名称而不是报错，属于静默错误
- 分隔：`v_sh600519="1~贵州茅台~600519~...";`

### 2.3 强制自校验

```python
assert abs(price - prev - chg) < 0.02          # 字段错位
assert 0 <= pct <= 31                          # 涨跌幅越界（北交所上限 30%）
assert amt_wan * 1e4 >= vol_hand * 100 * price * 0.5   # 量额量级不符
```

校验不过的行**直接丢弃并计数**。单轮失败率 > 0.5% 告警（源在改格式）。

### 2.4 代码 → 符号映射（北交所陷阱）

```python
def sym_of(code):
    c = str(code).zfill(6)
    if c[:2] == '92' or c[0] in '48' or c[:2] in ('43', '83', '87', '88'):
        return 'bj' + c        # 920xxx 极易误判成 sh！写错返回空，静默失败
    if c[0] in '69':
        return 'sh' + c
    return 'sz' + c
```

## 三、东方财富 push2（板块 / 资金流）

### 3.1 必须做的三件事

```python
HOSTS = ['push2.eastmoney.com', '82.push2.eastmoney.com', 'push2delay.eastmoney.com']
HEADERS = {'User-Agent': 'Mozilla/5.0 ...'}      # ← 只给 UA，绝对不要带 Referer

for i in range(3):
    host = HOSTS[i % 3]                          # 每次重试换域名
    try:
        return fetch(f'https://{host}{path}', headers=HEADERS)
    except Exception:
        await asyncio.sleep(0.25 * 2**i)         # 指数退避
```

实测：**裸请求 0/12 成功，带 Referer 全 FAIL，三次退避 11/12**。

### 3.2 `pz` 硬上限 = 100

| 传入 `pz` | 实际返回 |
|---|---|
| 100 | 100 |
| 500 | **100** |
| 2000 | **100** |

板块 496 个必须分 5 页拉；`pn` 从 1 开始。

### 3.3 常用 `fs` 参数

| 用途 | `fs` |
|---|---|
| 行业板块 | `m:90+t:2+f:!50` |
| 概念板块 | `m:90+t:3+f:!50` |
| 地域板块 | `m:90+t:1+f:!50` |
| 板块成分股 | `b:BK1347` |
| 个股全A（沪深） | `m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23` |
| 个股全A（含北交所） | 上面 + `,m:0+t:81+s:2048` |

**全A 口径三个数字必须固定一个**：沪深 5563 / 含北交所 5925 / 自有清单 5343。建议用自有清单，东财数字只做交叉校验（差异 >2% 告警）。

### 3.4 字段

| 字段 | 含义 | 单位 |
|---|---|---|
| `f3` | 涨跌幅 | % |
| `f6` | 成交额 | **元**（不是万元） |
| `f12` / `f14` | 代码 / 名称 | 板块的 f12 即 `BKxxxx` |
| `f62` | 主力净流入 | 元（超大单+大单） |
| `f66/f72/f78/f84` | 超大/大/中/小单净额 | 元 |
| `f104` / `f105` | 板块上涨 / 下跌家数 | 家 |
| `f128` / `f140` | 领涨股名称 / 代码 | 板块行专用 |
| `f184` | 主力净占比 | % |

### 3.5 逐笔成交

```
GET https://push2.eastmoney.com/api/qt/stock/details/get?secid=1.600519&pos=-15&iscca=1
```

返回 `data.details` 字符串数组，每行 5 段：

```
11:12:58,1337.99,12,12,2
  时间      价格   量  笔数 方向(1=卖 2=买)
```

`secid`：沪市 `1.600519` / 深市 `0.000001` / 北交所 `0.920xxx`。

**单只一次请求**，5563 只不可能全拉 → 只服务自选池（≤20 只），节拍不快于 5 s。

### 3.6 大盘分钟资金流

```
GET https://push2.eastmoney.com/api/qt/stock/fflow/kline/get
    ?lmt=0&klt=1&secid=1.000001
    &fields1=f1,f2,f3,f7
    &fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61,f62,f63,f64,f65
```

- `klt=1` 分钟级：实测当日 104 根（11:12 时点）
- `klt=5` 与 `daykline`：**本次返回 0 根**，不要用
- 末根示例：`2026-10-23 10:54,-21581268929.0,16852918112.0,4726008960.0,-1116568625`
  （时间, 主力净额, 小单, 中单, 大单 —— 具体顺序以实测核对为准）

## 四、东方财富 datacenter（龙虎榜 / 财务）

### 4.1 两个必踩的坑

1. **域名不是 `push2`**，是 `datacenter-web.eastmoney.com`，否则 404
2. **必须带 `sortColumns` + `sortTypes`**，否则静默返回 `count=null`（不报错）

```python
url = ('https://datacenter-web.eastmoney.com/api/data/v1/get'
       '?reportName=RPT_DAILYBILLBOARD_DETAILSNEW'
       '&columns=ALL&pageNumber=1&pageSize=50'
       '&sortColumns=TRADE_DATE&sortTypes=-1')
```

实测：龙虎榜 269,818 条，349 ms，字段含 `TRADE_DATE / BILLBOARD_DEAL_AMT / EXPLAIN / SECUCODE`。

### 4.2 不可用的 reportName

`RPT_STOCK_ZT_POOL`、`RPT_LIMIT_UP_POOL`、`RPT_MULTI_ZT_POOL`、`RPT_NOTICE_MAIN` 均返回 `count=null`。
→ 涨跌停家数**从全市场快照自算**（有 `limit_up`/`limit_dn` 字段，比池子接口更准更快）；公告需另接数据源。

## 五、坑位清单

| 现象 | 根因 | 修法 |
|---|---|---|
| 东财全部 `RemoteDisconnected` | 反爬，裸请求 0% | 域名轮换 + 3 次退避 + 熔断 |
| 带 `Referer` 反而失败 | WAF 规则变更（旧结论已失效） | **只带 User-Agent** |
| 板块只返回 100 条 | `pz` 上限 100 | 分页 `pn=1..5` |
| 龙虎榜 404 | 用了 push2 域名 | 换 `datacenter-web` |
| 龙虎榜 `count=null` | 缺 `sortColumns`/`sortTypes` | 补参数 |
| 中文名称乱码 | 腾讯返回 GBK | `decode('gbk')` |
| 北交所股票查不到 | `sym_of` 把 920xxx 判成 sh | 显式 `bj` 前缀 |
| 某指数涨跌幅永远 0 | 字段错位 | 断言 `p3-p4-p31≈0` |
| **科创板成交量比实际大 100 倍** | 腾讯对 688 返回「股」，其余返回「手」 | 用 `[35]` 成交额反推 `ratio=(额÷量)÷价`，≈1 为股、≈100 为手；外盘/内盘同步归一 |
| 09:30 前成交额排序全是垃圾 | 竞价数据成交额近 0 | 时间闸门，09:30 前禁用该排序 |
| 午休/盘后延迟飙到 20 s+ | **源端时间戳不推进，不是故障** | 延迟告警只在 09:30–11:30 / 13:00–15:00 生效 |
| 首轮全市场耗时 1.3 s、后续 0.4 s | urllib 无连接池，18 个 TLS 新建 | 验收统计排除首轮；M3 换 httpx 连接池 |
| 涨跌家数总数对不上 | 某批快照超时只回部分 | 断言 `涨+跌+平+停=总数` |
| 单位差 10000 倍 | 腾讯成交额是「万元」、东财 `f6` 是「元」 | 统一在解析层转换 |

## 六、实测延迟记录（同一日不同时段）

| 时间 | 时段 | 延迟中位 | 备注 |
|---|---|---|---|
| 10:54 | 盘中 | **3 s** | 单批 300 只 |
| 11:12 | 盘中 | **5.4 s** | 全市场 18 批 |
| 11:38 | 午休后 | **22 s** | 非交易时段时间戳不推进 |
| 11:45 | 午休末 | **9.9 s** | 静默 45 s 后回落 |

**专门做了对照实验**（`tools/bench_latency.py`）：静默 90 s 基线 22.1 s → 连打 8 轮全市场 24.8 s（未恶化）
→ 再静默 45 s 回落 9.9 s。**结论：滞后来自源端时间戳的更新节奏，不是限流降级、也不是网络问题。**

所以：
- 延迟告警只在连续竞价时段有意义
- 午休/盘后 UI 应显示「已收盘 / 价格冻结」，标红只会让自己误判系统出故障
